# 正常聊天时自动整理档案

在接入的工作区开始新会话时，助手收到私库中最新的协作偏好、表达风格和当前项目卡。提交消息时，本机程序提取明确的第一人称偏好和决定。每轮回答结束时，它再提取助手汇报的进展，合并重复条目，然后用 GitHub 文件接口提交到私库的默认分支。日常使用无需发送同步口令。

| 正常对话中的一句话 | 归档位置 |
| --- | --- |
| 我习惯先看一个例子。 | USER.md |
| 我喜欢文章用短句。 | STYLE.md |
| 我们决定先做纸质原型。 | 已绑定项目的项目卡。在档案本身开聊时记入 memory/decisions.md |
| 已完成首页草图。下一步是找两位读者试用。 | 当前项目卡，标注为助手交接 |

当前整理器按中英文表达规则提取短句。它会跳过临时要求、代码块和可识别的敏感内容。它不会理解所有措辞，意思相近但表述不同的条目可能并存。改口或需要合并长篇材料时，助手可以直接编辑相应 Markdown 文件。凭据原文应放进密码管理器。

## 让 Agent 一次接入

首次搭建会为检测到的本机客户端接入私有档案目录。要在业务项目聊天时也启用，把具体项目目录和所用客户端告诉搭建助手。下例中的两个路径由执行搭建的 Agent 换成实际目录。

```sh
python ai-profile-starter/tools/bootstrap.py --workspace "存放私有副本的目录" --client codex --project-dir "正在做的项目目录"
```

Claude Code 使用 `--client claude`，Gemini CLI 使用 `--client gemini`。可多次指定客户端。接入下一台设备或旧版模板生成的私有副本时，使用最新版公开模板再运行同一命令。已有副本有未提交改动时，搭建程序会报告暂缓本地接入。项目目录名决定项目卡名称，跨设备使用相同目录名可接续同一张卡。

接入后重开客户端会话，按提示信任工作区和回调。Codex CLI 可在 `/hooks` 中检查，桌面端可在设置的 Hooks 页面检查。项目配置会合并原有回调。若相应设置文件已经由业务仓库跟踪，检查差异后再提交，配置中含本机脚本路径。[Codex 回调](https://developers.openai.com/codex/hooks) · [Claude Code 回调](https://code.claude.com/docs/en/hooks) · [Gemini CLI 回调](https://geminicli.com/docs/hooks/reference/)

## 怎样知道它在工作

在已接入的工作区说「我习惯先看例子」，等助手回答后打开私库的 USER.md。应当能看到标有「本人偏好」的条目和一次「自动整理协作档案」提交。再开新会话问「给我解释一个新概念时，我偏好怎样开始？」。

联网失败或文件正被另一台设备更新时，已经提取的条目保存在私有副本的 Git 元数据目录中。下次开始会话或完成一轮时会自动重试。回调不保存聊天全文。同步直接更新 GitHub；查看本机 Markdown 或生成网页导出前，在干净的私库副本中运行 `git pull --ff-only`。

同一客户端里，只有已接入的工作区触发这些动作。普通网页聊天和仅有文件上传的助手，可以读取导出的档案；要自动写回，宿主需要提供可调用的对话事件和私库写权限。
